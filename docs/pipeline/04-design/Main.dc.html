Circular Array Queue

DS-015 Beginner Phase 1 Full tier 7 min read Mark as read
A first-in-first-out queue that stores elements in a fixed-size array and wraps the read and write positions around the end of the array — so nothing is ever shifted.
Builds on Static Array — you need to know how fixed-length arrays are indexed. Already comfortable with that? Skip ahead.
What it is
Picture a row of numbered lockers and two markers: one on the locker you'll read from next, one counting how many are in use. When a marker walks off the end of the row it comes back to locker 0. The queue never moves anything — the window of live elements simply rotates through the array. That single idea is what makes both ends O(1) with no allocation after the constructor runs.

When to use it

You know the maximum number of queued items in advance.
You need strict O(1) enqueue and dequeue with no allocation after construction — audio buffers, game loops, network read paths.
A resize pause would be unacceptable in your latency budget.

When not to use it

The maximum size is unknown or unbounded — it throws when full. Use a Linked Queue instead.
You need to insert or remove from the middle. Reach for a Doubly Linked List.
You're tempted to size the array defensively large — that memory is reserved up front, whether you use it or not.
You're writing production code and don't need to control the memory. java.util.ArrayDeque grows automatically and is faster than this for almost every workload.

18public class ArrayQueue<T> implements Queue<T> {
19    private final T[] data;
20    private final int capacity;
21    private int front;
22    private int size;
23
24    @SuppressWarnings("unchecked")
25    public ArrayQueue(int capacity) {
26        this.capacity = capacity;
27        this.data = (T[]) new Object[capacity];  // the only allocation
28        this.front = 0;
29        this.size  = 0;
30    }
31
32    @Override
33    public void enQueue(T item) {
34        if (size == capacity) {
35            throw new IllegalStateException("Queue is full");
36        }
37        int end = (front + size) % capacity;   // wrap past the end
38        data[end] = item;
39        size++;
40    }
Walkthrough
24–30 The constructor allocates once and never again. Every method after this point runs in constant space — that property is the entire reason to choose this over a growable queue.
37 The line that makes it circular. (front + size) % capacity is the first free slot; when the sum runs past the last index, % folds it back to the beginning. If you only remember one line from this page, this is it.
47–56 deQueue nulls the slot it vacates. Skipping that would still be correct, but the array would keep a reference to a dead object and stop the garbage collector reclaiming it.

Invariants it always keeps true

0 ≤ size ≤ capacity — enforced by the guard on line 34.
Live elements occupy exactly the indices (front + i) % capacity for i in [0, size).
Every slot outside that window is null — that's why deQueue clears as it goes.

Now rebuild it yourself

Code hidden
Open an empty file. You have the spec — the invariants above are all you need. Come back and compare when you're stuck, not before.
Allocate the array and set front and size in the constructor.
Write enQueue so the write index wraps. Throw when full.
Write deQueue so it clears the slot, advances front, and decrements size.
Prove it: fill it, drain it, fill it again. If the second fill fails, your wrap is wrong.
