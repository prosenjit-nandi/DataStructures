Link-Cut Tree

DS-059ExpertPhase 5 Explanation only 4 min read
There is no implementation on this page — on purpose
A link-cut tree is a splay tree of splay trees. Getting one to the repo's 100 % branch-coverage standard is several days of work, and almost nobody writing Java will ever need one. So this page explains what it is, what it costs, and what to use instead — and stops there. It is scheduled for phase 5 and will be marked Built if that changes.
Read the tier policyOpen an issue asking for it
What it is
A structure for a forest of rooted trees whose shape changes constantly — edges appear and disappear as you work. It answers questions about paths through those trees (the root of this node, the maximum edge weight along this path) in O(log n) amortized, while link and cut reshape the forest in the same time.
The trick is that it never stores the tree directly. It decomposes the forest into preferred paths, stores each path as a splay tree keyed by depth, and links those splay trees together. Every operation begins by splaying the node you asked about up to the root of its path.

When to use it

·Dynamic connectivity in a forest where edges are added and removed online — network reconfiguration, incremental MST maintenance.
·As the backing structure for a max-flow implementation that needs path updates in logarithmic time.

When not to use it

·The tree is static. Use binary lifting or an Euler tour + sparse table — an order of magnitude simpler and faster in practice.
·You only ever add edges, never remove them. A Union-Find does that in near-constant time in about twenty lines.
·Almost always, honestly. If you reach for this in application code, one of the two rows above is probably your real answer.
